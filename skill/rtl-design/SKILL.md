# 02 RTL 数据通路、控制对齐与模块设计

## 适用范围与使用方法

用于编写或修改PE、脉冲卷积点积、定点累加、偏置与阈值发放、末层输出。输入必须有量化/神经元契约、接口时钟/复位、吞吐要求和存储读延迟。先填写 [模块设计契约](assets/module-contract.md)，再使用 [spike_mac.sv](assets/spike_mac.sv) 及 [自检TB](assets/tb_spike_mac.sv) 作为可运行案例。

## 设计工作流

1. 用接口表定义每个信号的位宽、signed、时钟域、采样条件和有效周期。不要用名称推断复位极性或假定 `enable` 会暂停所有寄存器。
2. 列周期表：输入spike/weight同拍，分组和对应的fire/last/bias/threshold同时入寄存器，最终累加只在该事务valid时更新。空拍、clear、阈值触发和末层输出的优先级写成真值表。
3. 单比特脉冲与权重相乘化为选通；显式将每个有符号权重扩展到目标加法位宽。分组加法树先确保数学语义，再按关键路径决定进一步流水，不能用代码缩进证明平衡树。
4. 普通层输出spike，末层输出完整有符号累加；明确输出时是否同时清状态。任何模式切换必须等待在途数据清空，或随事务流水携带模式。
5. 写自检TB：固定边界+连续输入+空拍+clear打断在途事务+有符号负数+阈值相等+末层输出；检查valid的周期以及数值，不能只看波形“像是对的”。

## 模板契约与运行

`spike_mac` 是**本次新写的简化设计模板**：CHANNELS为8的正整数倍，默认32；每个lane是16位signed权重，spike为0/1；第一拍寄存每8路和及侧带，第二拍累加/发放。第一输入采样沿到输出更新沿相隔1个周期，即数据经过两个寄存处理阶段；轨迹记分板的 `--latency` 应按导出cycle定义填1，不能直接填阶段数2。

`fire` 表示本次点积完成一个发放判定，此时加入bias；`last` 表示输出完整累加并清状态，优先于普通层spike。last同时fire时仍加入bias。clear清累加和在途事务；无out_ready，消费者须接收每个out_valid。溢出是ACC_W位补码回绕，不做饱和。模板不实现原PE中的池化、反卷积、bypass、固定末层权重或多PE阵列。

在任意临时构建目录执行，源码使用绝对路径或按目录调整相对路径：

```powershell
xvlog --sv spike_mac.sv tb_spike_mac.sv
xelab tb_spike_mac -s skill_mac_test
xsim skill_mac_test -runall
```

通过时TB打印 `SKILL_MAC_PASS`；任一数值/周期差异或超时会 `$fatal`。运行记录见 `../validation/README.md`。这个TB证明模板行为，不证明原 `pe.v` 已重新完成等价验证或达到指定频率。

## 项目案例、踩坑与失效条件

- `rtl/pe/pe.v` 中32路spike选通权重，先8路分组再4组相加，bias和fire/ts_end分级寄存；这是拆解数据与控制的来源。新增模板体现这类方法，未照抄全部原PE的模式行为。
- `rtl/pe/pec.v` 生成32个PE，按组切分权重和bias，首层和末层有专门valid/输入选择。迁移时不能仅改PE_NUM：原代码还含固定32、31和分组索引。
- 原 `pe.v` 的多个模式引用不同延迟的控制；修改流水深度必须检查每条模式路径，不能只改输出valid。
- 组合块无默认赋值、signed混算、非阻塞赋值误用、data更新但valid未清零，都是需要用代码和反例确认的风险，不代表本项目每项都已发生过故障。
- 时钟/复位/背压规则变化或跨多个时钟域时，本模板失效；先扩展契约和验证，再生成RTL。某条源码注释写200MHz不能作为时序验收证据。
