# 01 算法到硬件映射与量化设计

## 适用范围与输入

用于从网络描述进入硬件设计，以及更换尺寸、通道数、时间步或定点格式时评估关联修改。输入包括实际模型 `forward`、量化/编码导出、目标精度及硬件预算。先沿实际 `forward` 核查分支；类中定义了模块不代表运行时使用，文件名中的“no_cat”也不能代替读取 `Up.forward`。

## 工作方法

1. 复制 [层契约表](assets/layer-contract.csv)，逐层记录算子、形状、padding/stride、通道组、时间步、权重/偏置、输出是脉冲还是累加值，标明参考来源。将PC编码和FPGA推理的边界单列。
2. 明确神经元更新顺序：先加权/偏置还是先阈值判断、相等是否发放、复位清零还是减阈值、膜电位是否跨时间步保留。不能仅因 `beta=1` 就认定软件神经元与RTL逐周期等价。
3. 为每层明确实数到整数的缩放、舍入、饱和/回绕，以及符号扩展。估计同号极值累加上界，单次32路和所需位宽与跨kernel/通道/时间步累加位宽分别预算。
4. 固定 `时间步→行列→通道/组→lane→字节` 顺序，用非对称小矩阵验证；层权重顺序与DDR/PE bank映射同时写清。
5. 使用 [numeric_reference.py](scripts/numeric_reference.py) 建小规模整数参考。先测0、负数、阈值两侧与极值，再测卷积/池化/反卷积/跳接；该工具只覆盖基础整数语义，完整算子参考需另补。

## 可复制提示词

```text
请把附带SNN模型映射为可实现的FPGA模块契约。材料包括实际forward、编码/量化导出、目标器件与资源预算。
先列逐层形状和算子，再列PC/FPGA边界；每条结论引用文件和函数。
明确时间步循环、膜电位保持/清零、阈值相等处理、bias施加时机、末层是否输出累加值。

输出一份层契约表，以及软件浮点、量化整数、RTL和目标热场四级参考的区分方法。
最后给一个非对称小张量和负权重边界用例，说明它们能排除哪些错误。暂不生成全系统RTL。
```

## 项目案例、来源与踩坑

- `pc_python/pre_process/our_snntorch_Unet_add_relu_vth_0999_train_static_coding_no_cat_haodong.py` 包含编码层、Down/Up、末层1×1卷积及 `Leaky(beta=1, reset_mechanism='zero')`；`SNN_Unet_incode_T3.py` 包含时间步循环、状态reset、权重/偏置round-clamp量化。历史脚本有绝对路径与顶层执行，分析时读源码，不为了检查而直接导入运行。
- `rtl/proj_snn.vh` 为UNET、T=3、32路输入、32路PE、16位权重、32位累加；`rtl/pe/pe.v` 的普通层发放与末层累加输出不同，不能都转为布尔脉冲。
- 控制ROM的 `in_ch_num` 与硬件端减一计数、group/lane定义需一起核对。将软件总通道数直接填入4位计数器可能截断。
- 权重在内存中的512位顺序与发送字节顺序不同，应先验证原始权重到反序权重的实际映射，不能凭“每若干字节反序”的旧注释实现。

## 验证效果与失效条件

本次基础参考通过正负极值、舍入/饱和、补码与点积测试；现有权重重排由传输技能对全部块进行核对。没有重跑训练或完整量化网络，不提供精度提升比例。`numeric_reference.py` 的舍入为ties-to-even、饱和为显式clip、累加为指定宽度补码回绕；新项目规则不同必须修改参考并增加反例，不能据基础测试认定全网络等价。
